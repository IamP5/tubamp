
# Amp-Sim Signal-Chain & Preset UX Research

Sources: Line 6 HX Stomp/Helix manuals & community guides, IK Multimedia TONEX/TONEX ONE/TONEX Pedal/TONEX Cab manuals, Kemper Profiler manual & forum, Neural DSP Archetype plugin docs/reviews, Neural Amp Modeler (NAM) official docs/TONE3000.

## 1. Signal-chain ordering models

**Flexible-chain products (drag-and-drop reordering):**
- *HX Stomp / Helix*: Fully reorderable block chain (HX Stomp caps at 8 blocks). No enforced order, but the documented/community best-practice convention is: `Noise Gate -> Compressor/Drive(s) -> Amp -> Cab(IR) -> EQ -> Modulation -> Delay -> Reverb`. Example high-gain preset: Gate(tight) -> Overdrive(as clean boost) -> Amp(high-gain) -> IR -> Parametric EQ(post-cab) -> Delay(short) -> Reverb(subtle). Example clean preset: Compressor -> Amp -> IR -> Chorus -> Trem/Rotary -> Delay -> Reverb. Input/Output blocks bookend the chain for gain-staging (Trim/Level); a separate always-on Global EQ sits after everything.

- *Kemper Profiler*: Semi-fixed two-zone topology, not freely reorderable end-to-end: `Stomps A -> B -> C -> D (pre-stack, serial) -> Stack (Amp+Cab, position fixed) -> Effects Section X -> Mod -> Delay -> Reverb (post-stack)`. Only the 4 pre-stack and 4 post-stack slots are assignable; the Stack itself is a fixed anchor point. X/Mod slots accept almost any effect type except delay/reverb; Delay/Reverb slots are reserved for those types. The dedicated Noise Gate is a control in the Input section, not a chain slot — placed as early as possible because dynamics are easiest to gate before any compression/distortion narrows the signal's dynamic range; users are told to duplicate a gate in Slot A if a second is needed.

- *Neural DSP Archetype plugins*: Semi-fixed sectioned UI: `{pre-fx/pedalboard} -> {amp} -> {post-fx incl. verb/trem} -> {cab, EQ, comp often bundled near cab}`. Pedalboard puts overdrive/boost/noise gate/compressor pre-amp. Some (newer) plugins allow full freeform reordering of the effects, but amp/cab position is generally anchored.

**Fixed-chain, capture-based product (TONEX) — the closest analogue to a NAM-centered plugin:**
TONEX/TONEX ONE full DSP signal flow (from official manual), a single fixed pipeline with each block individually placeable pre/post via a per-block Position toggle rather than free drag-reorder:

```
Instrument In -> Global Setup -> Trim In
 -> NOISE GATE (if position=FIRST)
 -> COMPRESSOR (if position=PRE)
 -> MODULATION (if position=PRE)
 -> DELAY (if position=PRE)
 -> TONE EQ (if position=PRE)
 -> TONE MODEL: AMP -> TONE MODEL: CAB   <-- the captured model itself, fixed center
 -> TONE EQ (if position=POST)
 -> NOISE GATE (if position=POST)
 -> COMPRESSOR (if position=POST)
 -> REVERB (if position=POST)
 -> MODULATION (if position=POST)
 -> DELAY (if position=POST)
 -> REVERB (if position=LAST)
 -> MAIN VOLUME -> Output
```
Key design insight: TONEX doesn't give users a free block-order canvas. It gives a **fixed slot count per FX type** (one gate, one comp, one mod, one delay, one reverb, one EQ) each with a **small enum of legal positions relative to the tone model** (pre/post, and gate additionally has "first"; reverb additionally has "last"). This is dramatically simpler to build and reason about than Helix/Kemper's freeform routing, while still giving users the two or three orderings that matter (gate-before-drive, reverb-after-everything, comp-before-vs-after-amp for character vs. leveling).

### Recommendation for a NAM-centered fixed-chain plugin
Adopt TONEX's model exactly: one fixed model slot (NAM capture + cab/IR) in the center, a small fixed set of pre/post FX blocks (gate, comp, EQ, mod, delay, reverb) each with a constrained position choice rather than arbitrary reordering. Good default fixed order:
`Input Trim -> Noise Gate(pre) -> Compressor(pre) -> [NAM Amp Model] -> Cab/IR -> EQ(post) -> Reverb/Delay/Mod(post) -> Output Volume`
with gate defaulting to "first" (before everything, including comp) and reverb defaulting to "last" (after delay/mod), matching both TONEX's and Kemper's convention that noise gates go as early as possible and reverb goes as late as possible.

## 2. Parameters exposed per block

**Noise Gate** (TONEX, HX Stomp, Kemper all converge on the same small parameter set):
- Threshold (dB) — level below which gate closes
- Release/Decay time (ms) — how fast it closes
- (Kemper's Input-section gate is a single knob = threshold, tuned via a simplified "Gate" control; Kemper's philosophy is fewer, better-tuned knobs)
- TONEX gate: single "threshold" knob is the primary user-facing control (auto/optimized attack-release under the hood) — confirms IK deliberately reduces gate to 1 knob for accessibility.

**Compressor**:
- HX Stomp / pedal-style comps: Threshold (dB), Ratio (X:1), Attack (ms), Release (ms), Mix (%), Level/Gain, Knee (dB) — full pro-audio compressor parameter set.
- TONEX compressor: simplified to a single "Threshold" knob with **automatic makeup gain** — again IK trades flexibility for one-knob usability.
- Design takeaway: two viable tiers — a "simple" one-knob amount/threshold control (TONEX-style, good default for a fixed-chain consumer plugin) vs. full threshold/ratio/attack/release/knee/mix (HX Stomp-style, good for an "advanced" panel).

**Amp/Tone-Model block** (TONEX, the direct analogue for a NAM plugin):
- Main knob layer: GAIN (drives the model), BASS (low shelf), MID (mid bell), TREBLE (high shelf), VOLUME (output level of the model)
- Alt/secondary knob layer (same physical knobs, shifted): DEPTH (chorus depth), REVERB (mix), COMPRESSOR (threshold w/ auto makeup), NOISE-GATE (threshold) — i.e., TONEX overlays "quick access" FX parameters onto the amp block's 3-knob control surface to avoid a cluttered full-chain UI, especially on the hardware pedal.
- PRESENCE control also present (high-frequency amp response, separate from EQ treble).
- Important nuance: because TONEX gain/EQ/volume are **not physically modeled parameters** (unlike Kemper/Helix component-level amp models) — they are captured-model **conditioning inputs** the neural model was trained across a parameter sweep of, or post-hoc DSP EQ/gain applied around a fixed capture. For a NAM-only plugin (since vanilla NAM captures are typically single fixed-setting snapshots, not full parameter sweeps unless using multi-parametric "AIDA-X"/parametric NAM training), the dev must decide: (a) expose only Input Gain (drive into the frozen model) + Output Volume + a standard post-model 3-band EQ (bass/mid/treble) as the "amp" character controls, since you likely won't have a real trained Gain knob unless doing parametric capture; or (b) if only single-point captures are supported, don't call the knob "Gain" — call it "Input Trim" / "Drive into model" to set expectations correctly.

**Reverb types** — convergent set across products: Room, Plate, Hall, Spring (physically modeled, associated with vintage combo amps), Shimmer (pitch-shifted reverb tail), Chamber. Helix additionally ships algorithmic/designer reverbs (Glitz, Ganymede, Searchlights, Plateaux) beyond the classic 5. TONEX reverb (post-block) is comparatively minimal — essentially a mix/amount knob layered onto the amp-block's alt controls rather than a dedicated multi-type reverb engine, reinforcing that TONEX treats non-model FX as secondary/utility, not a selling point.

**Delay types** — Helix ships 30+ delay models (tape, analog/BBD, digital, multi-tap, reverse, etc.) as the deep end of the spectrum; TONEX ships a much smaller fixed delay block (basic digital/analog delay with time/feedback/mix). Decision: a fixed-chain NAM plugin should ship a small (3-5 type) delay/reverb set rather than trying to compete with Helix's effects depth — that's not the differentiator.

## 3. How capture-based products handle the cabinet question

- **TONEX Capture (hardware capture unit) supports two capture modes**: (1) *with cabinet* — mic the cab as usual, capturing amp+cab+mic+room as one inseparable model; (2) *without cabinet / preamp-only* — capture direct from the amp's output (no mic/cab), leaving cab simulation to a separate IR stage. IK explicitly recommends users can capture **both simultaneously** (direct + mic'd) for maximum flexibility, and states TONEX's AI can even "remove" the cabinet's contribution from a mic'd capture after the fact to allow swapping in other cabs/mics — an ML source-separation trick, not simple subtraction.
- **TONEX plugin/pedal signal path always has a distinct, separate CAB block** downstream of the AMP/tone-model block regardless of whether the loaded Tone Model itself includes a captured cabinet. This CAB block: has its own IR slot(s) (up to 8 on TONEX Cab hardware), an **IR Enabled on/off toggle**, and a delete/trash icon to clear a loaded IR. Users can load third-party IRs in standard formats (wav) into this slot. So the product answer isn't "capture models the cab, full stop" — it's "give the tone-model author an explicit choice at capture time (with/without cab), AND always give the end user a downstream cab/IR block they can independently toggle/replace," which handles both capture strategies gracefully — a with-cab model can still get double-cab'd if the user forgets to disable the IR block, so IK's UI makes the IR toggle prominent and obvious.
- **Kemper's analogous mechanism ("Studio Profile" vs "Direct Amp Profile" + "Pure Cabinet")**: Studio Profile = amp+cab captured together (default/most common workflow); Direct Amp Profile = amp captured direct/without cab, meant to be paired with a separate cabinet portion of a Studio Profile at playback (Kemper supports merging a Direct Amp profile's amp with a different Studio profile's cab). "Pure Cabinet" is Kemper's ML-ish trick to strip the microphone's own coloration from a captured cab, analogous to TONEX's "remove cabinet after the fact" claim — both vendors converge on: full captures are inherently amp+cab+mic entangled, and any "toggle cab off" after the fact is an approximation/best-effort DSP trick, not a clean separation, and both surface this ambiguity to users via manual warnings.
- **NAM (Neural Amp Modeler) itself, the actual target)**: ships with a **built-in noise gate + built-in IR loader** as fixed plugin infrastructure around the neural model. The documented convention (per NAM's own site/TONE3000 guides) is: NAM model = amp+preamp+drive pedal nonlinearities (whatever was in the reamp signal chain when captured); IR = separate, always-on-top layer for cab+mic+room. Recommended user workflow is explicitly "load a NAM profile for amp character, then load an IR for cab voice" — i.e., NAM's own ecosystem convention is capture-without-cab + mandatory separate IR stage, differing from TONEX's dual-mode approach. **This is the most directly relevant fact for the target plugin**: if building on NAM captures, follow NAM's own convention (captures are typically cab-less; IR loading is not optional/toggleable-off, it's the primary cab mechanism) rather than TONEX's with/without hybrid — unless the plugin's capture format explicitly supports both, match user expectations set by the wider NAM/TONE3000 community (most shared .nam files on ToneHunt/TONE3000 are preamp+amp only, IR loaded separately).

## 4. Preset model / library UX

- **TONEX**: "Tone Models" (the neural network capture files, i.e., the NAM-equivalent) are distinct from "Presets" (a Tone Model + its pre/post FX chain settings + I/O settings = the full recallable preset, analogous to a "patch"). The **TONEX Editor** app has a **Librarian tab** that auto-syncs the entire local Tone Model + Preset + cloud ("ToneNET") library, with folder organization, filtering, and **Favorites** (star/flag a model to quickly load and push to a hardware slot). Factory presets carry rich metadata: bank, preset name, tone-model name, "character" tag, amp name, cab name, MIDI program-change number, plus song/artist/genre/style metadata enabling browsing by real-world context ("presets designed for real musical situations"), not just technical params. On hardware (TONEX Pedal/ONE) presets are organized into numbered **Banks** navigated via footswitch combos, a holdover from stompbox-era UX for hardware but largely irrelevant for a pure-software plugin (a software plugin should replace "banks" with a searchable/filterable library + tags + favorites instead).
- **Kemper**: separates "Rigs" (=preset: profile + all effects/stack settings) organized into Rig slots/banks with **5 favorite slots per Performance** on the hardware, plus a "Browse" mode with tagging (Amp, Character tags like Clean/Crunch/Lead etc.), and Rig Manager desktop software for librarian-style bulk organization, renaming, tagging, and merging cab-only/amp-only profiles into new Rigs.
- **Neural DSP plugins**: each Archetype plugin is scoped to one artist/amp model; presets within it are simple named preset slots (no cross-plugin library), often distributed as downloadable preset packs by third parties; A/B comparison is a common informal marketing device (third-party demo videos A/B one plugin vs. another) rather than a first-party in-app A/B feature in most Archetype plugins.
- **A/B / compare conventions**: Helix/HX has hardware-level **Snapshots** (up to 8 per preset) that instantly recall different parameter states of the same preset (e.g., rhythm vs. lead) — this is the closest first-party "instant compare" mechanic among these products, though it's a snapshot system (save multiple states) rather than a literal A/B toggle. A dedicated A/B slot pattern (load two whole presets, flip between them with one button, useful for comparing two capture models or two EQ settings) is common in DAW plugins generally but not a distinguishing named feature IK/Kemper/Neural DSP heavily market — worth building as a lightweight differentiator: two full preset "slots" (A/B) with one-click flip, independent of the snapshot/scene mechanic.

## 5. Input/output gain staging & noise-gate placement conventions

- **Helix/HX**: Dedicated **Input block** (Trim control, sets input gain before hitting any blocks) and **Output block** (Level control, final output trim) bookend the signal path; blocks/meters turn **red on clipping**, green when signal present — visual clip indicator is a expected UX convention. Global Settings > Ins/Outs offers a further global level adjustment layer independent of the preset. Recommended troubleshooting order when clipping: reduce source instrument level -> reduce Input block Trim -> reduce Output block Level -> reduce individual block gain (amp/effect) -> adjust Global I/O settings — i.e., gain problems should be fixed as early in the chain as possible, cascading outward only if needed.
- **Kemper**: Input section combines **Gain** (matches the incoming instrument's hot/weak signal to the profile's expected input level) with a single-knob **Noise Gate**, plus a **"Clean Sens"** control that balances perceived loudness between clean and distorted profiles without changing how hard the amp/effects are driven (i.e., a loudness-matching control that is deliberately decoupled from drive amount) — a subtlety worth replicating: separate "how hard am I driving the model" from "how loud does this preset sound at output," because with captures, driving the model harder often isn't even possible (fixed capture point) so a pure output/perceived-loudness trim matters more than on modeled amps. **Master Volume** is explicitly global (not per-preset) and always the final output stage across all presets — an important convention: a single always-on master output level independent of preset-level "Volume" avoids jarring volume jumps when switching presets/models.
- **Noise gate placement convention (near-universal across Kemper/HX/TONEX)**: gate goes as early in the chain as possible — ideally before any gain-adding block — because dynamic range between wanted signal and noise floor is largest at the raw input, before compression or distortion narrows it. Kemper explicitly documents this reasoning; TONEX's default/most-common gate position is FIRST (pre-everything, including pre-comp); HX Stomp community convention agrees (gate is almost always block 1). **This is the strongest, most consistent convention across all four products** and should be the hardcoded/default gate position in a fixed-chain plugin, even if the position is nominally configurable.\n\n## 6. Summary of concrete decisions for a NAM-centered fixed-chain plugin\n1. Fixed center block = NAM model (amp) + separate, always-present IR/cab loader block downstream (follow NAM ecosystem convention: captures are usually cab-less, IR is the primary/expected cab mechanism, not optional add-on) — but still give an IR on/off toggle in case a user's capture already includes a cab-like signal.\n2. Small fixed pre/post FX slot set, each with position choice, not freeform block reordering: Noise Gate (pre, default FIRST) -> Compressor (pre or post, default PRE) -> [NAM Amp + IR/Cab] -> EQ (post) -> Modulation (post) -> Delay (post) -> Reverb (post, default LAST).\n3. Two-tier parameter complexity per block: a simple \"one-knob\" mode (TONEX-style: single Amount/Threshold with auto behavior) as default, with an \"advanced\" reveal exposing full pro parameters (attack/release/ratio/knee for comp; threshold/release for gate) for power users.\n4. Amp-block controls: don't overclaim a physically-modeled Gain knob unless the capture format is parametric; ship Input Trim/Drive-into-model, Output Volume, and a post-model 3-band EQ (bass/mid/treble) + presence as the standard, expectation-matched control set (mirrors TONEX's Gain/Bass/Mid/Treble/Volume/Presence layout, which is the de facto genre convention users already expect from a \"tone model\" plugin).\n5. Reverb/delay: ship a small curated set (Room/Plate/Hall/Spring/Shimmer for reverb; 2-4 delay types) rather than trying to match Helix's 30+ delay/16 reverb depth — depth in FX is not the differentiator for a capture-centric product.\n6. Preset model: separate \"Model\" (the .nam/IR pair, analogous to TONEX Tone Model) from \"Preset\" (Model + FX chain + I/O settings, the full recallable unit), with a Librarian-style searchable/filterable/tag-based library (favorites, tags like amp type/genre/character) replacing hardware-era \"banks\" for the software UI. Add a lightweight two-slot A/B compare (not just multi-state snapshots) as a differentiator, since no reviewed competitor prominently ships true A/B.
7. Gain staging: separate concerns explicitly — Input Trim (source-matching, pre-gate) vs. per-model Drive/Input (how hard the model is driven, if parametric) vs. Output Volume (per-preset perceived loudness) vs. a global Master Output (always-on, preset-independent, prevents preset-switch volume jumps) — with visual clip indicators (green/red) on input and output meters per Helix convention.
8. Default gate position should be hardcoded first-in-chain (or default there) per the near-universal convention across Kemper/HX/TONEX that gating works best before any gain/compression stage narrows the dynamic range.
